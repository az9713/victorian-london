## Round-1 root cause and the fix that applies to the whole batch

Every "black void" the judge found (8 per door at rail/stile junctions,
both ends of the shopfront fascia, the row-joint hole) had the same cause:
**two separate primitives sharing an exact z-plane.** Cycles shadow rays
between two coincident coplanar faces self-intersect and the surface
renders solid black — this looks like a hole but is a lighting artifact on
real (if badly placed) geometry, not missing geometry, confirmed by a
control render: `blender/renders/B4/_nobevel_test.png` shows the same 8
black door-junction squares with the Bevel modifier fully removed, ruling
out bevel as the cause before any rework began.

**The fix, applied everywhere this pattern existed:** any two boxes that
need to touch now either (a) cross by >=25 mm (embed past each other's
plane) or (b) sit at deliberately different proud depths, never both
resting on the exact same z. Applied to: `plinth`, `string_course`, the
window sill in `window_sash`, the sign-bracket wall plate, downpipe
brackets, and every proud element in `shopfront_ground` (stallriser, frame
surrounds, panel-above-door, fascia, cornice). The door helper
(`door_leaf`) was rebuilt so rails sit *between* stiles (not through them)
at a shallower, different proud depth (stiles 17 mm proud, rails 14 mm —
was 45 mm, which the judge read as "open shelving"), both embedding 25 mm
back into the leaf base rather than touching its front face.

## r2 fix — roof coverage (defect found in-game)

**Defect as reported:** the slate roof covered only the front strip of each
module; seen from above, most of the 5.00 x 14.00 footprint was open
sky/hollow interior in the game.

**Root cause.** `parts.py`'s `roof_and_parapet` built the slate roof as one
bare `add_quad` — a single free-standing face with no matching backface and
zero thickness, unlike every other element in this scene (walls, plinth,
chimney, fascia, gutter), which are all `add_box` solids with real
thickness and verified outward-normal winding. Cycles clay renders don't
distinguish front/back faces, so this looked fine in every round-1/round-2
render; a real-time (in-game) renderer does backface-cull, and the quad's
winding put its facing side down, not up, so it read as transparent/absent
from directly overhead. Footprint x/z coverage in the code was already
correct (x=-2.5..2.5, z from the front parapet line to the back wall) — this
was a normal/thickness bug, not a missing-area bug.

**Fix.** `roof_and_parapet` now builds the slate roof as a solid wedge: 8
verts / 6 faces (top slate + an offset soffit 0.14 m below it + 4 closing
edges), vertex/face-index pattern mirrored directly from `common.add_box`'s
proven outward-normal convention (top face wound like `add_box`'s known-good
"top" face, soffit like its "bottom" face). Materials: top = slate,
soffit + all 4 closing edges = planks (bargeboard/soffit boarding). Existing
fascia, rafter tails, gutter, lead flashing and the brick gable-end infill
triangles (attic close-off) are unchanged — they were already `add_box`/
`add_tri` and not implicated.

**Verification — pixel count (the countable check).** Ortho top camera
(`cam_top`, `C.V(0,30,0)` looking straight down, `ortho_scale=14.0`) framed
so render resolution (250x700) exactly matches the 5:14 footprint aspect —
the *entire* rendered image is the footprint, no sub-region math needed.
Rendered with `film_transparent=True` so any gap is unambiguous (alpha=0)
regardless of world background color. Counted with a standalone PIL script
over every `terrace*-*_top.png`:

|---|---|---|---|
| terrace0-3 | 250x700 | **0** | 1371 (0.783%, outer silhouette only) |
| terrace0-4 | 250x700 | **0** | 1371 |

Zero fully-transparent pixels on all 6. The identical 1371 px "alpha<255"
